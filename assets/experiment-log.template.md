# 기록 형식

줄기 문서(`exp/<줄기>/BRANCH.md`)와 exp 문서(`exp/<줄기>/<exp>/EXP.md`)의 형식과 축 목록이다. 줄기·exp·실험이 무엇이고 언제 무엇을 쓰는지는 `CLAUDE.md`에 있다. 실험은 `exp/` 아래 경로로 가리킨다(`stack/nested/prune-fwd8/fwd`).

## 줄기 문서

```markdown
# <줄기 경로>

<이 줄기를 한 줄로>. 규칙은 `CLAUDE.md`, 형식은 `exp/TEMPLATE.md`.

## 구조

<대략적인 모델 구조. 단계와 데이터가 흐르는 순서. 왜 이 구조로 가는지(무엇을 검증하려는지). 하위 줄기면 부모와 무엇이 다른지>

## 상태

- 갈라진 곳: `<실험 경로>` — <갈라진 이유 한 줄>
- 상태: 작업
- 머리: `<실험 경로>`
- 대조: `<실험 경로>`
- 진행중: `<exp 경로>`, `<exp 경로>`
- 변동폭: <값> — <무엇의 표준편차인지>

## 다음 후보

- [ ] <후보> (예상 비용 / 기대 효과)
```

`구조`에는 단계별로 무엇이 들어가 무엇이 나오는지 적고, 구체적인 모델·피처 목록은 exp에 맡긴다.

| `상태` 줄 | 적는 것 |
|---|---|
| 갈라진 곳 | 부모 줄기에서 갈라져 나온 실험과 이유. 최상위 줄기는 `없음` |
| 상태 | `작업` / `보존 — <이유>` / `닫힘` |
| 머리 | 다음 exp가 그 위에 쌓이는 실험과 그 판정. 아직 없으면 `없음` |
| 대조 | 머리가 넘어선 직전 머리. 갈라진 직후에는 갈라진 곳의 실험 |
| 진행중 | 판정 전 exp. 없으면 `없음` |
| 변동폭 | 이 모델 구조의 변동폭과 그것이 무엇의 표준편차인지. 아직 못 쟀으면 `미측정`, 하위 줄기가 부모와 같으면 `부모와 같음` |

## exp 문서

```markdown
# `<exp>` — <이 exp를 한 줄로> · <판정>

- 시작:
- 모델:
- 피처:
- 결합:
- 대조:
- 조건:
- 결론:
- 보관:

## `<실험>` — <바꾼 것 요약> · <판정>

- 축:
- 바꾼 것:
- 결과:
- 가설:
- 해석:
```

| 머리말 줄 | 적는 것 |
|---|---|
| 시작 | exp를 연 날짜. 번호가 없으므로 시간 순서는 이 줄과 git 이력으로 본다 |
| 모델·피처·결합 | 이 exp가 구조를 어떻게 채우는지. 예: 스택이면 1단계 멤버(이 exp의 실험 이름이나 다른 exp의 실험 경로), 만들어 쓰는 피처와 어느 모델에 들어가는지, 메타·가중 방식. 이미지라면 백본, 입력 해상도·증강, TTA. 줄 이름은 세팅 시 과제에 맞게 정한다. 멤버가 많으면 계열별로 묶어 적고 전체 목록은 결합 실험의 `config.yaml`에 둔다 |
| 대조 | 이 exp가 비교되는 실험. 보통 줄기 머리 |
| 조건 | 분할·seed·데이터. 대조와 다른 점이 있으면 무엇이 왜 다른지 |
| 결론 | 판정할 때 쓴다. 대조보다 나은지, 이 exp의 실험 중 다음 exp에 가져갈 것과 버릴 것, 머리로 올릴 실험. 판정 전에는 비워 둔다 |
| 보관 | 정원 밖이어도 산출물을 남길 이유. 이유가 없으면 이 줄을 두지 않는다 |

| 실험 항목 필드 | 적는 것 |
|---|---|
| 축 | 아래 `축 목록`의 값 하나 |
| 바꾼 것 | exp의 구성(또는 다른 실험)에서 무엇을 바꿨는지 |
| 결과 | 세 신호(개선폭 대 변동폭, 일관성, 분산 변화)가 읽히는 형식 |
| 가설 | 왜 이렇게 바꿨는가 |
| 해석 | 왜 그렇게 나왔는가. 진단이면 재현 명령도 |

필드는 세팅 시 이 대회에 맞게 확정한 것이다.

## 축 목록

실험 항목의 `축`에 쓰는 값이다. 세팅 시 이 대회에 맞게 확정한다.

- `data` — 정제·분할
- `feature` — 입력 표현
- `model` — 구조·크기
- `objective` — 손실·타깃 변환
- `training` — 최적화·스케줄
- `ensemble` — 결합·스태킹

## 예시

**테이블 · 3단계 스택** — `exp/stack/BRANCH.md`

```markdown
# stack

1단계 멤버 예측을 메타로 쌓고 메타들을 다시 섞는 3단계 스택. 규칙은 `CLAUDE.md`, 형식은 `exp/TEMPLATE.md`.

## 구조

1. 1단계 — 서로 다른 계열의 멤버(GBDT·신경망·선형 등)가 같은 fold로 OOF·test 예측을 낸다. 멤버마다 입력 피처가 다를 수 있다
2. 2단계 — 멤버 OOF를 logit으로 바꿔 메타 모델 여럿(LR 등)에 넣는다. 메타는 학습 fold 안의 holdout으로 규제를 고른다
3. 3단계 — 메타 예측을 nested 가중 평균(caruana)으로 섞는다
4. 후처리 — 필요하면 3단계 출력에 규칙 기반 보정을 붙인다

단일 GBDT로는 계열마다 잡는 신호가 달라 점수가 한 모델에서 멈췄다. 서로 다른 계열의 오차가 상쇄되는지를 검증하는 구조다.

## 상태

- 갈라진 곳: 없음
- 상태: 작업
- 머리: `stack/fe-members/stack`
- 대조: `stack/base-members/stack`
- 진행중: `stack/meta-te`
- 변동폭: 0.0004 — 1단계 멤버의 seed만 바꿔 세 번 쌓은 OOF AUC의 표준편차

## 다음 후보

- [ ] 1단계에 TabM 추가 (멤버 학습 40분 / 신경망 계열이 하나뿐이라 몫이 있을 수 있음)
- [ ] 메타 입력에 원본 범주 target encoding (`meta-te` 판정 뒤)
```

**그 줄기의 exp** — `exp/stack/fe-members/EXP.md`

```markdown
# `fe-members` — 1단계 GBDT 셋을 파생 피처 입력으로 바꾼 스택 · 채택

- 시작: 2026-11-10
- 모델: `lgbm-fe`, `xgb-fe`, `cat-fe` (이 exp), `stack/base-members/mlp`, `stack/base-members/lr`
- 피처: 원본 24열. GBDT 셋에는 자릿수·수치 쌍 곱·조합 빈도 370열을 더한다(`src/features.py` `GROUPS`)
- 결합: 2단계 LR 메타 하나 → 3단계 없음
- 대조: `stack/base-members/stack`
- 조건: folds.csv v1, seed 42 — 대조와 동일
- 결론: 대조보다 0.0012 높고 다섯 fold 모두 올랐다. `meta-te`는 다음 exp로 가져가고 `post`는 버린다.
  머리로 `stack`을 올린다.

## `lgbm-fe` — LightGBM, 파생 피처 입력 · 기준

- 축: feature
- 바꾼 것: `stack/base-members/lgbm`에서 입력을 원본 24열 → 파생 피처 포함 394열로
- 결과: CV 0.9471 ± 0.0011 · fold별 [0.9458, 0.9480, 0.9469, 0.9485, 0.9463]
- 가설: 자릿수·곱 피처가 원값 분할로 잡히지 않는 신호를 준다.
- 해석: 원본 입력판보다 다섯 fold 모두 높다. 중요도 상위 20개 중 9개가 파생 피처다.

## `stack` — 다섯 멤버 LR 스택 · 기준

- 축: ensemble
- 바꾼 것: 이 exp의 구성 그대로
- 결과: CV 0.9521 ± 0.0009 · fold별 [0.9510, 0.9530, 0.9518, 0.9533, 0.9514] · LB 0.9503
- 가설: —
- 해석: 대조보다 +0.0012(변동폭 0.0004의 3배), 다섯 fold 모두 상승. LB도 같은 방향.

## `meta-te` — 메타 입력에 범주 18열의 target encoding logit 추가 · 보류(유망)

- 축: encoding
- 바꾼 것: `stack`의 메타 입력에 fold 안 target encoding logit 18열
- 결과: CV 0.9524 ± 0.0010 · fold별 [0.9512, 0.9534, 0.9520, 0.9535, 0.9519]
- 가설: 고유값이 많은 범주의 값 단위 신호를 멤버가 다 담지 못한다.
- 해석: +0.0003으로 변동폭 수준이지만 다섯 fold 모두 올랐다. 멤버를 바꾼 다음 exp에서도 남는지 본다.

## `post` — `stack` 출력에 사기 0건 구간 후처리 · 보류(중립)

- 축: ensemble
- 바꾼 것: train에서 사기가 0건인 값 구간의 예측을 최솟값으로 내림
- 결과: CV 0.9521 ± 0.0009 · fold별 [동일] · LB 0.9504
- 가설: 0건 구간은 test에서도 0건이다.
- 해석: CV는 그대로이고 LB만 +0.0001이다. 노이즈와 구분되지 않는다.
```

```markdown
- 결론:

## `base` — 이 exp의 구성 그대로 · 기준

- 축: resolution
- 바꾼 것: 대조에서 입력 512 → 640
- 결과: val mAP@0.5 0.612 ± 0.005 (run별 0.607 / 0.615 / 0.614) · best epoch 평균 41
- 가설: 소객체가 512에서 몇 픽셀로 줄어 사라진다.

## `mosaic-p05` — mosaic p=0.5 추가 · 진행중

- 축: augmentation
- 바꾼 것: `base`에 mosaic p=0.5
- 결과: val mAP@0.5 0.615 ± 0.011 (run별 0.603 / 0.621 / 0.621) · best epoch 평균 47
- 가설: 소객체 검출이 배경 다양성 부족으로 약하다.
- 해석: 신호가 엇갈림. 개선폭 0.003, 일관성은 3 run 중 2 run만 개선, 분산은 0.005 → 0.011로 확대.

  전자는 기존 로그로 확인 가능, 후자는 재평가 5분 — 이 exp에 `mosaic-p05-small-ap` 실험으로 더한다.
```

**갈라진 줄기** — `exp/stack/nested/BRANCH.md`

```markdown
# stack/nested

멤버의 멈춤 시점을 학습 fold 안 holdout으로 고르는 3단계 스택. 규칙은 `CLAUDE.md`, 형식은 `exp/TEMPLATE.md`.

## 구조

`stack`과 같은 3단계 구조다. 다른 점은 1단계 멤버가 early stopping 지점을 검증 fold가 아니라 학습 fold 안에서 뗀 holdout으로 고른다는 것 하나다. 점수 수준이 달라져 `stack`의 exp와 나란히 비교할 수 없다.

## 상태

- 갈라진 곳: `stack/fe-members/stack` — 멈춤 시점을 고르는 방식이 바뀌어 점수 수준이 달라졌다
- 상태: 작업
- 머리: `stack/nested/fe-rebuild/stack` (기준)
- 대조: `stack/fe-members/stack`
- 진행중: `stack/nested/add-tabm`
- 변동폭: 부모와 같음

## 다음 후보

- [ ] `stack`의 `다음 후보` 중 이 조건에서 다시 볼 것을 옮겨 온다
```
