# EDA

데이터를 봐서 알아낸 것을 담는다. 대회가 정한 규칙은 `docs/competition-spec.md`에 있다.

**헤딩 규약**: `##`은 관찰 범주, `###`은 개별 관찰이며 `###`이 덮어쓰기 단위다. 새 관찰이 나오면 해당 `###` 내용을 교체한다. 기존 `###`에 해당하지 않으면 `###`을 새로 만들고, 기존 어느 범주에도 속하지 않으면 `##`을 추가한다.

아래 범주는 테이블 데이터 기준의 출발점이다. **데이터에 맞게 조정한다** — 시계열이면 정상성·계절성을, 이미지면 해상도·클래스별 샘플 수를 추가하고, 해당 없는 범주는 지운다. 개수를 맞추려고 관찰을 맞지 않는 슬롯에 넣지 않는다.

**시점 기반 헤딩을 만들지 않는다.** "추가 분석", "2차 EDA", "업데이트", "현황"처럼 언제 썼는지를 가리키는 이름은 반드시 누적되고 기존 슬롯과 중복된다. 헤딩 이름은 항상 관찰 대상을 가리켜야 한다. **헤딩에 속하지 않는 문단을 문서 끝에 붙이지 않는다.**

쓰기 전에 슬롯 목록을 본다.

    grep -n "^#\{2,3\} " EDA.md

각 항목에 **관측값**을 적는다. `확인함`, `문제 없음`은 채운 것이 아니다. 수치나 구체적 사실을 적는다. 아직 안 봤으면 비워 둔다.

이 문서의 관찰은 fold 설계의 근거가 된다. `docs/validation-design.md` 0절 참조.

## 구조

fold 설계에 직접 쓰이는 범주다.

### 그룹 축

같은 개체가 여러 행에 걸치는가. 어떤 컬럼인가. 개체당 평균 행 수.

### 시간 축

시간 컬럼 유무, train 범위, test 범위, test가 미래인가.

### 계층

지역·카테고리 등 중첩 구조.

### 중복 행

완전 중복 건수와 비율. 근사 중복(리사이즈본, 미세 변형) 여부.

## train / test 관계

### ID 교집합

건수와 비율. 없으면 test가 새 개체이므로 group split이 필요하다.

### 분포 차이

기간·지역·카테고리별 비율 비교.

### adversarial validation

수행했으면 AUC와 상위 기여 피처. 해석은 `docs/validation-design.md` 3절.

## 타깃

### 분포

분류면 클래스별 건수·비율, 회귀면 요약통계와 치우침.

### 불균형

소수 클래스 비율, 최소 클래스 절대 건수.

### 이상치·절단

상하한 절단 여부, 극단값 처리 필요성.

## 결측·이상치

## 확인했으나 특이사항 없음

**이 범주만 누적한다.** 같은 확인을 반복하지 않기 위한 기록이다. 한 줄씩 적고 `###`을 만들지 않는다.
