# EDA

데이터를 봐서 알아낸 것을 담는다. 대회가 정한 규칙은 `docs/competition-spec.md`에, 헤딩을 쓰는 규칙(`###`이 덮어쓰기 단위, 시점 기반 헤딩 금지)은 `CLAUDE.md` `기록 위치`에 있다.

각 항목에 **관측값**을 적는다. `확인함`, `문제 없음`은 채운 것이 아니다. 수치나 구체적 사실을 적는다. 아직 안 봤으면 비워 둔다.

이 문서의 관찰은 fold 설계의 근거가 된다. `docs/validation-design.md` 0절 참조.

## 데이터 개요

### 파일과 규모

| 파일 | 행 | 열 | 비고 |
|---|---|---|---|
| | | | |

### 행의 단위

한 행이 무엇을 의미하는가.

### 조인 키

파일 간 결합에 쓰는 키와 카디널리티.

## 구조

fold 설계에 직접 쓰이는 범주다.

### 그룹 축

같은 개체가 여러 행에 걸치는가. 어떤 컬럼인가. 개체당 평균 행 수.

### 시간 축

시간 컬럼 유무, train 범위, test 범위, test가 미래인가.

### 계층

지역·카테고리 등 중첩 구조.

### 중복 행

완전 중복 건수와 비율. 근사 중복(리사이즈본, 미세 변형) 여부.

## train / test 관계

### ID 교집합

건수와 비율. 없으면 test가 새 개체이므로 group split이 필요하다.

### 분포 차이

기간·지역·카테고리별 비율 비교.

### adversarial validation

수행했으면 AUC와 상위 기여 피처. 해석은 `docs/validation-design.md` 3절.

## 타깃

### 분포

분류면 클래스별 건수·비율, 회귀면 요약통계와 치우침.

### 불균형

소수 클래스 비율, 최소 클래스 절대 건수.

### 이상치·절단

상하한 절단 여부, 극단값 처리 필요성.

## 결측·이상치

### 결측 패턴

| 변수 | 결측률 | 패턴 |
|---|---|---|
| | | |

결측이 무작위인지, 특정 조건에서만 발생하는지 적는다. 후자면 결측 자체가 신호다.

### 이상치

변수별 이상치 판정 기준과 건수.

## 주요 변수 관찰

전 변수를 나열하지 않는다. 타깃과의 관계가 뚜렷하거나 처리가 필요한 것만 `###`으로 추가한다.

## leak 후보

`docs/validation-design.md` 2절 체크리스트에 대응한다.

### ID·행 순서

인덱스와 타깃의 상관, 데이터가 타깃 순으로 정렬됐는지.

### 미래 정보

미래 시점에만 알 수 있는 변수.

### 메타데이터

파일명, 타임스탬프, 파일 크기 등에 담긴 정보.

## 열린 질문

아직 답하지 못한 것. 답이 나오면 해당 `###`으로 옮기고 여기서 지운다.

## 확인했으나 특이사항 없음

**이 범주만 누적한다.** 같은 확인을 반복하지 않기 위한 기록이다. 한 줄씩 적고 `###`을 만들지 않는다.

- 예) 매장 ID와 타깃의 상관: -0.01, 무의미
